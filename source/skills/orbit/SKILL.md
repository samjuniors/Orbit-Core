# Orbit orchestration in Antigravity desktop

Apply the `orbit` lead agent in `.agents/agents/orbit.md` and the specialist definitions under `.agents/agents/`. **The active Antigravity model is the reasoning engine.** Do not start Gemini CLI, Claude Code, or Codex CLI for Orbit.

- On start/resume, read current project instructions and canonical docs, check Git state, and use `orbit_project_resume` from `orbit-core-native` MCP when connected.
- **Fresh project preflight (before a stack or PLAN):** load `references/PROJECT-INTAKE.md`. Interpret everyday requests such as 'build a todo app', classify product type, complexity, maturity and risk; ask 2–5 high-impact questions with clear **Recommended** choices and a **Use recommendations** shortcut. Await answers unless user explicitly chose defaults. Do not reinterview a resumed/established project.
- **Documentation before implementation:** load `references/DOCS-AND-CONTEXT.md`, inventory owner docs by purpose, create only necessary nonduplicate vision/architecture/roadmap/design and product-type-specific docs through writer/architect or the lead host when delegation is unavailable. `.orbit/PROJECT.md` is an approved compact index to canonical owner docs, not a rival source. Produce a compact faithful agreed brief and targeted references, not recurring enormous prompts.
- Plan milestone → gate → executable steps, including frontend, backend, data, security, tests, CI/CD and deployment when applicable. Detail the nearest milestone and avoid overengineering.
- Delegate with host-native `invoke_subagent` only if genuinely available and authorized. Before dispatch, preview/register a stable scoped task (`orbit_task_plan`) and reserve a slot (`orbit_task_reserve`) using the real user/host approval; after successful native invocation record its real session reference (`orbit_task_started`). Release failed reservations. This MCP never launches an agent or runs a model. The orchestrator owns task selection, dependencies, file boundaries, review, and next steps; child agents never self-authorize more spawning.
- Prefer isolated branches/worktrees for simultaneous code changes if the host supports them. Otherwise do tasks serially. Never edit overlapping files concurrently.
- Agents return verifiable diffs, tests, status and blockers; Orbit checks the actual diff and tests, then records task outcome (`orbit_task_report`) and separately reviewed acceptance (`orbit_task_review`) before dependent tasks. Neither reported evidence nor task review is independently attested by MCP.
- Save checkpoint to `.orbit/STATE.md` through `orbit_project_checkpoint` with fresh revision and explicit approved `confirm_write`. Preserve existing user documents/ADRs and do not duplicate source of truth.
- Memory is SQLite local only when MCP connected. No remote API, paid model, automatic agent process, cloud sync, or user data export is implied by skill installation.

Read `references/TASK-LIFECYCLE.md` for the native agent ledger workflow and `references/HANDOFF.md` for a bounded handoff. Apply only when delegation is actually needed.

## Local application preview (v0.24 feature candidate)

For a new app, after approved implementation, inspect the actual package scripts, plan tests, and prefer the existing IDE browser. To preview the running app, call `orbit_preview_start` with `confirm_run: false` to show the **exact** shell-free argv and loopback URL. Re-run with `confirm_run: true` only after actual user/host permission to execute that project's code; use `orbit_preview_status` and inspect readiness and logs. Open the returned `http://127.0.0.1:<port>/` using an available host browser. Run real user interaction tests through the host browser or Playwright only when installed and permitted. If the host separately exposes approved Vercel Labs `agent-browser` MCP tools, use accessibility snapshots and authorized DOM interactions as supplemental evidence, not as an automatic replacement for Orbit's gated Playwright verification. Configure localhost domain allowlists; no auto-install, browser credential/profile reuse, remote navigation or public sharing. See `docs/AGENT-BROWSER-OPTIONAL.md` in the Orbit repository. Do not equate HTTP 200 with UI test success. Use `orbit_preview_stop` with `confirm_stop: true` to shut down the locally managed process when finished.

No cloud deployment, public tunnel, remote sharing, third-party auto-install, or background AI agent execution is included in these MCP tools. The preview's process tracking lives only in the active MCP process; after a host/MCP restart it cannot safely adopt or stop previously spawned processes.


## End-to-end local app workflow (v0.24 candidate)

When user asks to build an app from one prompt, use the host's normal coding and agent abilities. Orbit owns the sequence: (1) `orbit_build_begin` and project audit, (2) right-sized milestone/API contracts, (3) skill selection plus approved native specialist task delegation or serial implementation, (4) independent CLI tests and diffs, (5) permissioned `orbit_preview_start` and READY probe, (6) permissioned `orbit_browser_qa` with at least one actual user interaction and screenshot, (7) reviewer verification / repairs with bounded retry budget, (8) `.orbit/STATE.md` via guarded checkpoint, and (9) advance to DONE. Call `orbit_build_status` on resume to avoid repeating completed stages; its SQLite ledger tracks evidence, not invisible background model work.

`orbit_build_advance` records bounded caller-reported evidence; PREVIEW stage requires a currently READY Orbit-owned preview and preview_id, BROWSER_QA requires a recorded passing interactive Playwright result, CHECKPOINT requires an Orbit-managed checkpoint. Treat failed browser/CLI tests as blockers and use the host's approved repair ability; do not bypass a blocked gate. Browser QA is optional if unavailable, but then the run remains on HOLD rather than claiming success. Never expose public tunnels/deploy/commit/merge without distinct user permission. The local preview process still needs cleanup before closing MCP; across host restarts the *build state* is durable, not the running preview process.
