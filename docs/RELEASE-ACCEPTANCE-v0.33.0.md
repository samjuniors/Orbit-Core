### Remaining P0/P1/P2 risks

- **P0 — Untrusted preview release gate.** Default `NORMAL` and legacy execution remain available. `GUARDED` blocks preview and browser QA. The required LPAC backend checks token and job identity, while the host must separately provision and verify least-privilege ACLs, credential scope and endpoint policy. The prototype has no accepted Python preview path or authenticated per-action sensitive execution grant. Before publishing with RAD isolation in scope, require the selected host to enforce project, operation, consent, expiry and revocation, and show controlled filesystem/credential and network outcomes on the actual supported runtime. Owner scope and publication approval are pending. [Guard](https://github.com/samjuniors/Orbit-Core/blob/26a15a4e97f66f37f0c8f2286d033efc1558ec1b/source/runtime/orbit_defense.py#L95-L138) · [Host provisioning contract](https://github.com/samjuniors/Orbit-Core/blob/26a15a4e97f66f37f0c8f2286d033efc1558ec1b/source/runtime/orbit_appcontainer.py#L332-L363)
- **P1 — Confirmed by source review: readiness can escape the cleanup HOLD.** The isolated session remains in the registry after cleanup raises. Status and browser QA then consult process liveness and an HTTP response, without checking whether the isolated session has an authenticated endpoint. A repeated start can also return `ALREADY_RUNNING` with a healthy-looking readiness payload. Keep cleanup-pending sessions discoverable only for recovery, require one readiness decision across callers, and make stop retryable after job close. The existing endpoint regression covers successful cleanup. Dynamic failure-path reproduction was **NOT RUN**. [Preview start, status and stop](https://github.com/samjuniors/Orbit-Core/blob/26a15a4e97f66f37f0c8f2286d033efc1558ec1b/source/runtime/orbit_preview.py#L264-L366) · [Browser QA readiness](https://github.com/samjuniors/Orbit-Core/blob/26a15a4e97f66f37f0c8f2286d033efc1558ec1b/source/runtime/orbit_browser.py#L144-L154)
- **P1 — Containment and recovery remain process-local.** A caller that can name a validated root can intentionally trigger its containment. The 64-root budget limits escalation tracking for additional roots, and restart clears the policy state. Scoped memory covers three MCP tools and retains legacy rows under `NORMAL`; shared SQLite/WAL, backups and other project-data paths need independent access-control and rollback checks. Establish trusted, revocable recovery and verify LPAC descendant, controller-failure and partial cleanup handling. Include the suspended orphan window in the legacy Windows launcher. [Dispatcher](https://github.com/samjuniors/Orbit-Core/blob/26a15a4e97f66f37f0c8f2286d033efc1558ec1b/source/runtime/orbit_mcp.py#L804-L812) · [Memory policy and migration](https://github.com/samjuniors/Orbit-Core/blob/26a15a4e97f66f37f0c8f2286d033efc1558ec1b/scripts/migrate_scoped_memory.py)
- **P2 — Deferred scope and assurance.** The Linux/macOS LPAC-required path holds. Independent non-Windows sandbox support, protected audit evidence and signed artifact provenance remain future work. Attach redacted native run output with commit/tree, OS, controller and child results for each gate. A separate adversarial assessment of the integrated host/OS policy remains open.

Release acceptance still requires an owner decision about RAD inclusion, a reviewed versioned candidate, final exact-source CI and artifact checks, and the applicable native permissions, cancellation, installer and rollback gates from the canonical release procedure.
